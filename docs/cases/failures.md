# Ways a filing goes wrong

These are the failures the tests catch before any hardware gauge. The fixture list is `fixtures/failures.json`. Flock cameras is the seed. Library fines is the fresh topic that has to pass the same bar.

## Same argument, new axis

Two wordings of mass surveillance share `invasion-of-privacy`. A post that is actually about legality is `illegal` or `legal`. Those keys stay off the privacy and security directories. A single post that names two keys that already exist is listed from both, still one file. That listing is not a merge. Cross-links in `pairs.json` are links. They are not a merge, and `try_rename` refuses to fold legality into the other pair. The spill case is [spill.md](spill.md).

## A reason is not a key

Borders, elections, and crime are reasons inside `national-security`. Children forgetting a library book is a reason inside `returns-books`. A new reason for an existing one-liner does not mint a directory. A sentence does not become a slug. Keys are lowercase, spaces become hyphens, and a sentence-length slug is rejected.

## Choice is not the final slot

On submit a person may choose a category that already exists. The post is filed there, and that is only the default. They cannot type a new key. If they choose nothing, the post stays in `uncategorized` until the batch. A live suggestion does not file the post. The batch may move the post, including one placed by hand, or also attach the same body to another existing key. When a key moves, the old name stays in `key-history.json` so the old URL resolves. A non-argument is stored. If it names no argument, it stays uncategorized.

## Rename plus history

Any key with posts may be renamed when the posted rules leave keys to the SI. `mass-surveillance` becomes `invasion-of-privacy` in one commit: the page index, `key-history.json`, the comment files, and the votes all move together. The old name stays in the index so the old URL opens the current key. A `rules.md` that says keys never change freezes that rename. `mass-surveillance` stays.

## The batch does not churn

The position is the short form. The posts remain under it. A second pass with no new post and no new pair does not commit. An edited body re-queues the job. The author still does not set the key or the summary. A vote does not rename a key or rewrite a position, and it does not create a poll file.

## Solo first comment

One comment and no second person still yields questions on that key and a suggested opposing one-liner with a cited source. The opposing directory is absent until a user submits the first words there. The subscriber is told the section was updated. They are not told merely because another comment was posted.

## The record

Comments and votes store the incremental id. The UUID appears in `users/index.json` and not again. Issued ids start at 1 and are not reused. A commit whose author is not `clevertree-chat-ai`, an anonymous write, and a binary are rejected. Git commits pass `-c user.name` and `-c user.email` on the command. They do not run `git config`.
