A new way to debate.

You write one post. It lands on the point you’re making — not buried under a reply chain. Same small effort as a comment, a clearer debate for everyone watching. SI (Super Intelligence, i.e. AI) organizes the map; it does not vote or pick winners. A new kind of forum, still run by people.

Don’t get lost in the weeds.

A topic and a one-line argument make the address. Sentences that make the same argument share a key. A different reason stays beside it, so someone watching can see the debate.

One post can sit in more than one key when those keys already exist. “These cameras are illegal mass surveillance.” is listed under invasion-of-privacy and illegal, and it stays one comment. A new key opens only when a post does not fit. “but it's illegal!” spills into illegal. The Patriot Act is cited as a suggestion. It is not opened as a directory.

Why is this SI different from other SIs?

Clevertree Chat uses the same Relay pattern as MyProblem and QuizGate: batch SI (Super Intelligence, i.e. AI) on temporary hardware — not a permanent cloud brain you only audit through a retention policy. Typical cloud AIs stay attached to always-on services; leftover retention is what you hope a vendor honored. Here leftover retention is the exception the rules chose to keep.

Ephemeral batch hardware

Jobs run on interruptible Rackspace Spot GPUs (and similar temporary capacity). When the batch finishes — however long or detailed — the worker is decommissioned and scratch is destroyed, including inputs from apps, APIs, and other servers. Capacity exists only while the job runs, so thorough organization stays cheap.

Reconstructed SI, rules as memory

Each batch rebuilds the SI from programmed instructions: repo rule sets, and sometimes per-page or per-ticket rules. It has no durable private memory of prior runs beyond those instructions and what the standing debate map already publishes. When the batch ends, that instance is gone.

Retain only by decision

A raw enqueue does not become standing debate state until the batch accepts it under those rules. Only then does the allowed filing land in the map. Everything else dies with the job.

Why this is harder to hack than a policy-bound cloud SI

An always-on cloud stack can publish any retention policy and still leave caches, temp disks, logs, and replicas that outlive the promise — and those layers can be breached later. Here the attack surface for raw batch inputs is mostly the live job. When the Spot worker dies, the scratch dies with it; there is no long-lived “AI server” holding last week’s posts “just in case.” Absence of durable scratch is the control — not a policy you have to trust was never broken or bypassed. Low Spot cost is why that design stays practical.

On Clevertree Chat that means SI organizes the map so a unique perspective can be heard; it does not vote, pick winners, or take sides. People alone supply preference. More on the manifesto: Forest.

Daily loop: organize today, patch tomorrow

Each day we review what the standing map and batch queue need, assess the product, and ship site or host updates—often the next day. A small A-team plus LLM agents works at the development cadence of a major organization. The edge is visibility: private, accurate signals from tips and batch outcomes (not identity dossiers) so we can respond in near–real time. Same Clevertree method as QuizGate, MyProblem, and Clevertree.

North star: much of this loop becomes automated so a detailed user report can drive triage and a fix without a developer in the middle. SI still curates only—no votes, no winners. Builders: see /dev.

Make your opinion finally heard.

A post joins the one-liner it actually makes. When it is a different argument, it opens a new one. The page does not pick a winner — and neither does SI. It curates and organizes so the debate stays fair and legible; people alone supply preference. It takes no sides.

A post can belong to more than one argument, or to none. A new argument appears when a point spills out of the ones already there.
